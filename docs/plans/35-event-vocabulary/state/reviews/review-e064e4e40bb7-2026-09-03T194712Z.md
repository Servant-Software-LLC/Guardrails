## The pattern, recorded because it is now three-for-three

**B1 is the third consecutive plan broken by a closed-world tripwire no task owns.** Plan 33 broke
`BreakdownSalvageAllowListTests`; plan 34's *merge* broke this exact test (the repo's own corpus row for
plan 34 says so, calling it "the tripwire-no-task-owns defect of #587 arriving for the second time in two
plans"); plan 35 broke it **at breakdown** — creating the folder was enough, before any task ran.

The row can only be added by hand, because it carries the breakdown commit's own sha, which does not
exist when the plan's tasks are authored. **That is why it keeps being forgotten, and it is a gap in
`/plan-breakdown`, not in this folder.** Every future plan hits it. Further evidence for **#587 check B**.

**B2 and B4 share one root:** a signature change whose complete call-site set nobody owns. The plan's own
§5.1 doctrine — *"put every edit needed to restore compilation in a single task"* — was applied to
`AttemptFinished` and then not applied to the constructor. B2's root cause is narrower and is the author's:
the breakdown grepped **declarations** over `tests/` and **calls** over `src/`; the set difference is
exactly the one unowned file. The claim was measured, and the command could not see the case.
