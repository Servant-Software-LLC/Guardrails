## Why this addendum exists

The first real run halted at the wave-1 entry gate. The halt was **correct in outcome** (the preflight
did detect a non-zero `dotnet test`) but **wrong in diagnosis**.

## Finding — baseline preflight misattributes a non-zero exit as test failure

| Task | Guardrail | Sev | What it got wrong | Fix | Outcome |
|---|---|---|---|---|---|
| `wave-01/preflights` | `01-baseline-core-…`, `02-baseline-integration-…` | **BLOCKER** | Both treated ANY non-zero `dotnet test` exit as "the existing tests are ALREADY failing". The real run exited non-zero with **`Failed: 0, Passed: 11`** — an xUnit **class-cleanup fault** (`Test Class Cleanup Failure … TestPipelineException`, filed as **#433**). The gate therefore halted the run declaring healthy tests red, sending any reader to "fix" tests that were passing. | Three-way diagnosis on the parsed `Failed: N` count: **`Failed: 0`** → name it as NOT pre-existing breakage and point at cleanup/host (citing #433); **no summary at all** → runner/host died before reporting, explicitly not evidence of red tests; **`Failed: N>0`** → the genuine pre-existing-red message, now naming N. | **FIXED** |

Smoke-tested (#302): both files parse clean, and the classifier was exercised against all three log
shapes — the #433 cleanup-fault log, a genuine `Failed: 3` log, and an `MSB1009` no-summary log — each
producing the correct verdict.

## Issues filed from this run

- **#432** — a FAILED wave entry gate persists **nothing** on disk (the halt reason was terminal-only;
  a PASSING gate *is* recorded under `waves.<wave>.entry`, so success is logged and failure is discarded).
  This is why the fix above required the maintainer's scrollback to diagnose at all.
- **#433** — `RetrySalvageTests` intermittent class-cleanup `TestPipelineException`: non-zero exit with
  zero failing tests. Suspected the #116 Windows read-only `.git/objects` disposal trap; reproduced under
  the harness's `_integration` worktree, clean 2/2 in a normal checkout.

## Verdict

BLOCKER addressed. Plan re-validated to exit 0, diagram regenerated, baseline re-locked.
**Approved to stamp.**

Note the underlying #433 flake is NOT fixed by this plan — the gate will still halt if the cleanup fault
recurs, but it will now say so accurately instead of blaming the tests.
