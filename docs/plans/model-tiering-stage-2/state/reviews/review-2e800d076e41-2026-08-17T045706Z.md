## The three blockers and how they were resolved

### 1. `tierSource` was not computable — RESOLVED by adding a task pair

`PlanLoader.cs` collapses the two sources at load:

```csharp
Tier = rawAction?.Tier ?? defaultTier;   // ~line 1120
```

`ActionDefinition` kept no provenance, so nothing downstream could distinguish `task` from
`plan-default` — and `PlanLoader.cs` was in **no** `writeScope` in the plan. Wave 2 would have hit a
wall it could not write its way out of. Shipping without the fix means emitting `tierSource: "task"`
100% of the time: a green run carrying a wrong value, which is precisely the Stage 1 failure this
stage exists not to repeat.

Note the shipped workaround is *also* wrong: `PlanValidator.cs` guesses with
`tier != plan.Config.Tiering?.DefaultTier`, which misreports whenever a task's own tier equals the
default — the common case, not an edge case.

**Fix:** a new wave-1 pair, `05-author-tests-tier-provenance` / `06-implement-tier-provenance`,
restoring the destroyed information as `ActionDefinition.TierOrigin` (`None`/`Task`/`PlanDefault`).
Chosen over widening wave 2's `writeScope` because it is a distinct deliverable with its own
verification, and it is upstream of the wiring that consumes it. It carries `dependsOn: []`, so it
runs **parallel** to the resolver chain and costs no wall-clock (tiers 0 and 1 each fan out to 2).

`override` is deliberately **not** the loader's business: a pin is visible to the resolver directly
(D31), so only the genuinely-destroyed distinction is restored.

The pinned test `ActionTier_SameTokenAsDefault_OriginIsStillTask` is the one that matters — a
comparison-after-the-fact implementation passes every other test in the file and fails only that one.

### 2. §6.1 item 3 contradicted §6.2/D26 — RESOLVED as DoR **D30**

Item 3 read *"no effective tier, **or no block serves it** → legacy fallback"*, while §6.2/D26 says
the second half **halts** (`no-route` → needs-human, "does not quietly drop to a weaker rung"). One
condition, two opposite sanctioned behaviours. This was the sharpest of the three: task 03's coverage
guardrail requires a legacy test while wave 1's requires `no-route`, so an implementer taking either
reading fails the other's test, gets contradictory retry feedback, and dead-ends at `needsHuman`.

**Ruling (D30):** the disjunction is severed in favour of D26. **Legacy is the no-rung path,
`no-route` is the no-candidate path, and nothing is both.** Once an effective tier exists, resolution
owns the outcome — climb, then `no-route` — and never falls back to the runner's model. This keeps
GR2048 as the static gate, `no-route` as the runtime residual it should have caught, and legacy as
the untouched status quo for plans that never opted into tiering. The other reading would have made
`no-route` nearly unreachable.

Encoded in the folder as a **new required behaviour** in task 03 (prompt + coverage clause), in the
wave-2 brief, and as a new terminal-gate clause.

### 3. `tierSource: "override"` had no producing rule — RESOLVED as DoR **D31**

§12.4 listed the enum value; §6.1 defined nothing that emitted it. The worked example (§15, task 04)
showed a pinned task producing it, so the intent was recoverable.

**Ruling (D31):** a full `action.runner`/`action.model` pin is its producer. "Bypasses tier
resolution entirely" governs what is *selected*, not what is *logged* — a pinned attempt records
`tierSource: "override"` with `provenance.tier` **absent**, and a legacy-fallback attempt records no
`tierSource` at all. Every v1 enum value now has exactly one producer, and §12.4 carries the table.

## Findings from this round's own smoke tests

Every guardrail touched was **executed** against synthesized valid and invalid inputs (#302, and
#468's proposal 3), not read. Three findings, all caught by execution:

1. **`\"` is not a PowerShell escape.** A draft of the new `01-build-passes.ps1` used
   `\"needsHuman\"` inside a double-quoted string. Measured: it emits a literal backslash and
   **terminates the string**, splitting the message across lines — with **exit 0**. A guardrail whose
   failure message is silently garbled still fails the task, but the agent gets mangled retry
   feedback. Rewritten with no inner double quotes.

2. **Task 03's bare legacy clause could not be earned independently.** D30's negative test is
   naturally named `..._NeverFallsBackToLegacy`, which contains `Legacy` — so the *negative* test
   credited the *positive* clause, and a file asserting only the boundary went green on both.
   Negative lookbehinds do not fix it (the negation and the token are not adjacent), and widening
   them starts rejecting legitimate names like `NoTierAnywhere_UsesLegacyPath`. **Deleted** rather
   than patched: the positive legacy proof is already the Invariant-7 clause (fixture (b) *is* the
   legacy path) plus the `defaultTier` clause. Re-measured: all six remaining clauses are now
   independently earnable, with no cross-credit.

3. **The terminal gate holds at 0/8 on an unbuilt tree.** The v2 design of that gate went 10/14 green
   against a tree with type declarations and no wiring. Re-measured with the two new clauses: an
   unbuilt tree scores **0 of 8**, a wave-2-complete suite scores 7/8 (missing only the judge clause
   wave 3 owes — the intended ratchet), and a full suite scores 8/8. Four near-miss test names
   (`RoutingEnabled_ZeroTagPlan_UsesLegacyPath`, `EffortOverride_DoesNotBypassResolution`,
   `CostlyOnlyRung_SettlesNoRoute_NeedsHuman`, `ActionModelPin_OverridesModelString`) falsely credit
   **neither** new clause.

The new coverage guardrail for task 05 is a **behaviour manifest over discovered test names**
(`--list-tests`), not a regex over file text — the #468 form. Measured: correct suite 0 missing; the
lazy suite correctly red; dropping *only* the equal-values test correctly red on exactly that clause;
lowercased names correctly rejected (`-cmatch`).
