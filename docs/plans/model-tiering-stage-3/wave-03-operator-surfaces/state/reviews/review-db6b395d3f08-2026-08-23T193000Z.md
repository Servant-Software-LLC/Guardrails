The original bundling had a real justification — single ownership of the shared stub, so three tasks do
not all write `IRunObserver.cs` and collide at the union (#175). The stub task preserves that while
making each retry cheap. **The DAG is also strictly better**: each implement task now waits only on its
own 5 / 4 / 3 behaviours instead of all twelve.

The stub task's guardrail carries **inertness bans** that did not exist before and are now load-bearing:
`LiveRunObserver` must NOT declare `AttemptModelResolved` (that is `06`'s deliverable, and
`LiveObserver_DeclaresAttemptModelResolved_RatherThanInheritingTheEmptyDefault` is red only while it has
not), and `AttemptModelSummary` must throw. Without them a "stub" task that quietly does the work would
turn three downstream TDD reds green on arrival. Two-level strip applied (#470): required clauses read
comment-stripped source, bans read comment-and-literal-stripped, because the doc comment this task is
told to write legitimately names the banned token.

Renumbering left stale `task 0N` references in the gate comments and three prompts; all replaced with
durable **folder names** rather than new numbers (#203).
