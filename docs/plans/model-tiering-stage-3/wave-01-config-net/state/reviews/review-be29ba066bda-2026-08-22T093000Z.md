## Accepted residuals — recorded, not fixed

- **W1 (partial).** Nothing guards the GR2060/GR2061/GR1011 reservation markers in `DiagnosticCodes.cs`.
  A task that deletes the whole marker block still passes. Guarding every unrelated reservation from
  this task is out of proportion to the risk now that B2's false red — which made "delete the confusing
  block" the attractive escape — is gone.
- **W6.** `Guardrails.Integration.Tests` is not run by the exit gate. Deliberate: the wave changes only
  validator diagnostics, and the integration suite is 7–10 minutes. If a GR20xx warning does break an
  integration assertion, the plan-root terminal gate (wave 3) is where it surfaces.
- **The silence census cannot prove a silence test is real.** A hollow `Assert.True(true)` named
  `SilentWhenTieringNotConfigured` passes it exactly as a genuine `Assert.DoesNotContain` does. A red
  baseline cannot exist for a negative assertion; closing this needs mutation testing. **Invariant 7's
  protection in this wave rests on a human reading the three silence test bodies.** Stated here because
  a green census must not be read as more than it is.
- **`02 ‖ 04` parallelism kept.** The DA recommended linearizing on risk-posture grounds; its own
  finding disproves the premise — `AssignDependentHandles` gives a multi-dependency task a fresh segment
  off the plan-branch tip and every segment commit here is one file, so wave 1 cannot produce a conflict
  at all. A simplification, not a safety fix.
