## BLOCKER — task 05's composition-root proof is satisfied by a mention

**Measured, not argued.** I wrote a mutant test file whose only references to the two required symbols
are inside `nameof(...)` — no invocation of anything — and ran the guardrail against it:

```
mutant references:  var a = nameof(InitialBreakdownInvoker.PrepareInvocation);
                    var b = nameof(RunReset.Fresh);
real invocations:   0
guardrail exit:     0     <- GAMED
positive control:   0     <- the committed .valid sample still passes, so the check is not broadly broken
```

Both required clauses are **dotted-NAME** regexes (`InitialBreakdownInvoker\.PrepareInvocation`,
`\bRunReset\s*\.\s*Fresh\b`), and `nameof(Type.Member)` is valid C# containing that exact text. This is
Probe B **operator 9** landing. `02-breakdown-command-wires-the-gate.ps1` shares the hole — its
`\bDeclaredCountGate\s*\.` alternative matches inside `nameof(...)` too.

**Why this is a BLOCKER and not a nit: task 05 authors its own test.** Its `writeScope` includes
`tests/Guardrails.Core.Tests/PlanSource/PlanSourceWiringTests.cs`, so there is no upstream test-author
task and **no TDD-red half** — nothing else in the plan can tell a real composition-root test from a
hollow one. The complete gaming path is therefore:

1. write `PlanSourceWiringTests` with two dead `nameof` references and a passing assertion → `01` exits 0;
2. the same hollow test passes → `04-wiring-tests-pass` exits 0;
3. put `DeclaredCountGate.` anywhere in `BreakdownCommand.cs` → `02` exits 0;
4. the solution still builds → `03` exits 0.

**Task 05 goes green with nothing wired** — precisely the #120 built-but-unwired false green the task
exists to prevent, and the plan's own stated purpose (Half B) is the thing left unproven.

The guardrail's own `# catches:` line anticipates the *seam-injecting* variant (a test that writes
`plan-source.json` itself) and blocks it correctly. It does not anticipate the *mention* variant.

**Fix (both files):** require the invocation, and ban the mention.

```powershell
if ($code -cnotmatch 'InitialBreakdownInvoker\s*\.\s*PrepareInvocation\s*\(') { … }
if ($code -cmatch 'nameof\s*\(\s*[A-Za-z_][A-Za-z0-9_.]*\s*\.\s*(PrepareInvocation|Fresh)\s*\)') { … }
```

Stronger still, and worth considering instead: make the test assert on **what the production call
produced** — that `state/plan-source.json` exists on disk *after* `PrepareInvocation` returned, with a
`sourceSha256` matching bytes the test hashed itself. That is the #382 assertion requirement (an effect
only the production implementation emits) and it is not gameable by any text mutation.

guardrail 02   nameof mutant  exit=1  (was 0)   VALID exit=0   INVALID exit=1

**Deliberately NOT added: a `nameof` ban.** Requiring the call already kills the operator; a separate ban
would be redundant against gaming and would false-red a legitimate test using `nameof` in an assertion
message. Fixing the anchor is the whole fix.

## Amendment — the WEAK finding was overruled, deliberately, 2026-08-29

**Task 06 is back to `easy` (Haiku) at the maintainer's direction. The reviewer's recommendation stands
as written and was not withdrawn; it was weighed and declined.**

Their reasoning, and it is better than mine: *"Haiku failing may teach us something."* This plan exists
to produce the #230-lite measurement that gates the v2 bets (#227/#228/#231), and a rung that is safely
right measures nothing. The `easy` tag is the only end-to-end test of the cheap rung in the plan — bump
it and the run answers a question nobody asked.

**What the reviewer's finding still buys, now that it is on the record rather than in the config:** if
task 06 fails, the cause is already named and does not have to be re-derived at 2am. `SchemaDriftTests`
byte-compares `docs/plans/02-schemas-and-contracts.md` and `.gitattributes` pins it `eol=lf`, so a
reflowed line or a normalized ending fails a *drift test*, not task 06's own guardrail — and with #228
deferred to v2 the retry lands on the same rung rather than escalating. **Expect the failure to look
like an unrelated test breaking, not like a weak model missing its target.**

This is the WEAK severity working as intended: an opinion about difficulty, phrased as a rung, handed to
the human who owns the trade-off. Recorded here because a finding that is silently reverted is
indistinguishable from a finding that was never made.
