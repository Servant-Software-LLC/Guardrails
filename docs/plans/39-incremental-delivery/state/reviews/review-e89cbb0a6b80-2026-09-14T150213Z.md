## Accepted residuals

1. `guardrails attach` doesn't replay `WaveDelivered` (no task owns `AttachCommand.cs`).
2. No log-site panel for a `DeliveryRefused` halt; it shows on the console and in `observer.jsonl`. A failed trial-tree gate halts through `halt` and does show on the log site.
3. `MergeOnSuccessResult.BranchMoved`'s XML summary still describes only a switched checkout. Adding the file to task 31 raised GR2042 (structural over-scope: 75 turns and 4 files).
4. Task 31's cleanup of a crashed attempt's leftover trial ref and worktree is unpinned. The failure mode is loud: `git worktree add` fails.
5. **Crash between the refresh commit and `RecordRefreshed`:** no `refreshed[]` record names that commit. The quiet-case resume fast-forwards onto it, and §4 records the one re-announcement. This is the same commit-then-record window as plan 40's `supplied[]`.
6. A missing serial or opt-out guard in task 08 first surfaces at task 29's forward census. Both rows are green on base, so they cannot be red at task 07.
7. No real-Scheduler row stamps `DecisionEntry.Wave` at the proceeded-best-guess site. It fails safe: a null `Wave` holds rather than halts.
8. No SSOT clause pins the order of the marker relative to the settled delivery.
9. **Untracked gate artifact:** an artifact at a path the user's branch tracks blocks the refresh on every resume. The abort names the blocking paths.
10. Two deliberate evasions still pass the real-provider checks: a three-fragment string concatenation and a unicode-escaped identifier. No cooperative agent writes either.
11. **Census driver artifact:** in phase 2, the `.cmd` fake hands `|` to cmd.exe as a pipe, which yields 25 anomalies on the five `A|B`-filter scripts (tasks 04, 08, 13, 19, 31). Each script was proven with a `.ps1` fake and against real `dotnet`.
12. *(Resolved during this review.)* The user-global skill copies predated plan 40. Guardrails v1.20.0 was released from master (`5b2b0bbf`), the global tool was updated, and `guardrails skills install --force` restamped `guardrails-domain-knowledge`, `guardrails-review` and `plan-breakdown` at 1.20.0.
13. `DiagnosticCatalogueTests` is red between tasks 03 and 04 by design (#709); task 03's prompt warns against "fixing" it.
14. A rewound wave's re-run that is refused or held replaces the kept `delivered` record, while the earlier delivery's commits stay on the user's branch. If the run then stops before its run-end merge, the report can call that work held. Design §4 records this limitation.

15. The doc guardrails' sentence clauses (hold rule, final-wave rule) can't tell a rule from its negation, and nothing rejects a leftover round-4 sentence that lists `hook-rejected` among the halting refusals. A doc check is a lower bound; the prompts carry the exact wording.
16. Re-running a rewound, delivered wave usually conflicts, because `guardrails reset` rewinds the plan branch with `reset --hard` and the re-run rewrites work the user's branch already has. It converges: merge by hand, then resume. A warning in `guardrails reset` output would need `RunReset.cs`, which no task owns.
17. Unverified, and it predates round 5: rewinding past a refresh merge commit, which carries no `Guardrails-Task:` trailer, may be refused by `SafeSuffixEvaluator`.
18. A gate that relies on untracked state in the integration worktree (build caches, restored tools) fails only on a fresh trial tree. Its exit-gate headline then names the user's commits; the gate logs show the real cause.

19. Nothing pins that task 19 calls `RenderWaveDeliveryReport` on the run path. Task 18's row calls the renderer directly, so either of these passes every row while a husky run prints nothing:
    - a gated call;
    - a report printed inline, leaving the renderer unused.

    Neither is the cheap path. A static wiring check or a CLI-driven hook row would close it.
20. The rule that `--merge-on-success` never lifts a hook hold is stated only in the prompt; no row runs a hook rejection with the override on. Getting it wrong costs one more run of the rejecting hook after the operator forces delivery.
21. Two things were not measured:
    - the runtime cost of the Integration passes added to tasks 15, 17 and 29, against the plan's 1800-second default guardrail timeout;
    - the hook fixtures on Linux or macOS.
