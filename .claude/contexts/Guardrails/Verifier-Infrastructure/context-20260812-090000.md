- **#443 macOS crash — the big one.** `guardrails run` crashed 100% on macOS 26.6 / Apple Silicon with a
  native `AccessViolationException` (exit 134). **THREE of my diagnoses were wrong**, each corrected by
  evidence:
  (a) "the `--` pathspec separator" — wrong (the original reporter's theory);
  (b) "switch off `BeginOutputReadLine`, read synchronously" — **disproved by .NET source**: in
      `PipeStream.Unix.cs` BOTH `ReadCore` and `ReadAsyncCore` go through
      `SafePipeHandle.PipeSocket → CreatePipeSocket → new SafeSocketHandle`, the exact faulting frame.
      `ProcessRunner.cs` is UNCHANGED — the refactor was abandoned;
  (c) "ReadyToRun is the precondition" — wrong; we never set it.
  **Real cause: `EnableCompressionInSingleFile=true`.** A compressed bundle is the only case routing
  image load through `FlatImageLayout::LoadImageByCopyingParts`, which mprotects RW→RWX; on Apple
  Silicon that intermittently leaves pages non-executable. Upstream **dotnet/runtime#112167** (closed as
  dup of #123324, fixed by **PR #127355** → .NET **11**, not 10). Fix: `COMPRESS=false` for `osx-*` only.
  **The fingerprint that closed it:** every crash frame upstream is FRAMEWORK code and no Guardrails
  frame ever appears — our IL is JIT'd into fresh memory. "Both streams redirected" was correlation, not
  mechanism. **Confirmed in the field** by a falsification test (framework-dependent package → 3 real
  ProcessRunner spawns all passed on the same machine that crashed 100%).
- **#437** `needsHarnessWrite` demanded FULL content → files >~100KB unreachable. Added the anchored

BLOCKERS/NOTES:
- **Self-hosting hazard — the arc's biggest lesson.** Running Guardrails ON the Guardrails repo means a
  guardrail that runs this repo's own suite has SIDE EFFECTS on the tree it protects, and a task that
  changes harness behaviour breaks the harness's own pinned tests. Both run failures and this halt all
  trace to that.
- **`allowedTools` is a FLOOR** — it grants, it can never withhold.
- **There is NO write-time writeScope enforcement** — `WorktreeContainmentHook` enforces worktree
  containment only; `WriteScopeCheck` is retroactive for BOTH git and tool writes.
- `mark-reviewed --evidence` needs ABSOLUTE paths pre-#430; fixed but worth knowing for old builds.
- **NuGet: the flat-container index publishes minutes BEFORE the search index** `dotnet tool` reads.
  "Indexed" on flatcontainer ≠ installable. Poll `azuresearch-usnc.nuget.org/query`.
- A `guardrails run` on this plan costs real money (~$2 for a partial wave-1; more now it reaches wave 3).
- Known load-sensitive flake: `HarnessWriteRunTests.Worktree_RecoversClaudeWall_GuardrailTimesOut…`
  fails under full-suite CPU contention, passes in isolation. Belongs to
  `docs/plans/harden-flaky-worktree-test/`. Real baseline is 1960/1/2, not the 1961/0/2 I quoted earlier.
- **Pattern worth repeating:** three times a confident diagnosis was WRONG and empirical evidence
