--- Maintainer rulings worth not re-litigating ---
- **`costly` is TRI-STATE** (overrules the DoR's "absent = false"). Three states in the SCHEMA, TWO at
  the predicate: `ServesTier` is `Costly is not true`, so absent AND explicit-false both serve — an
  un-annotated registry must stay routable. The third state is what lets `providers init` find the
  NOT STATED ones and ask; "absent = false" made that unaskable.
- **A comment a human DELETED must not come back.** The skip is keyed on "the key exists", not "a comment
  is near it" — stickiness is structural, no marker written into the user's file.
- **Hand-code Stage 1.5 + workstream B** (not through Guardrails): enumeration means network calls and a
  flaky guardrail erodes trust in a whole run.
- **Difficulty maps to a candidate SET, not to strength**: tier tag → blocks whose `routing.tiers`
  contains that rung → ordered by ASCENDING strength → first wins. A `hard` task gets the WEAKEST model
  the operator declared capable of hard. NO numeric tier→strength mapping, and a hard task whose only
  capable blocks are costly fails validate (GR2048), never escalates.

IN PROGRESS — the macOS symlink saga (the ONLY thing blocking the v1.6.0 tag):
- `cb39c5c` (#450) made `WorktreeSweepBookkeeping` compare a git-reported path against a harness-derived
  one through a new `RealPath` walk. It was **green on Windows and RED on macOS CI** — my own fix's tests
  failed on the OS the fix was for.
- **Root cause, confirmed by three MacBook probes that eliminated suspects in order:** (1)
  `ResolveLinkTarget` is leaf-only and *throws* on a missing path; (2) `/var` **does** resolve — killing
  the API-blind-spot theory; (3) the walk works end-to-end in isolation. That left exactly one shape: **a
  link whose target is absolute but written in the ALIASED spelling.** The walk adopted such a target
  verbatim and threw away the canonicalisation it had already accumulated. macOS supplies the outer link
  for free — `LinkedTree` builds under `Path.GetTempPath()`, i.e. `/var` → `/private/var`.
- **FIX COMMITTED as `a05e3b8`** (reviewed by hand + `RealPathTests` 8/8 green on Windows before commit).
  Re-canonicalises every adopted target from its root, bounded by `MaxLinkDepth = 40`, degrading to the
  literal rather than throwing (a runaway is real and NOT circular per-link — `/x/a → /y/a` with `/y → /x`
  — so the runtime's SYMLOOP detection never fires).
- **The bug is UNREACHABLE through the Windows filesystem, and that was PROVEN, not assumed**: Windows
  resolves via `GetFinalPathNameByHandle`, which canonicalises the whole path, so `returnFinalTarget:true`
  always hands back an already-canonical target. Hence the new internal seam
  `RealPath.ResolveWith(path, resolveSegment)` with an injected resolver, and two tests proven **by
  mutation on Windows**: adopting verbatim → `Expected: C:\real\inner, Actual: C:\alias\inner`; removing
  the depth guard → **stack overflow, exit `0xC00000FD`**.
- Also discovered: `Directory.CreateSymbolicLink` fails unprivileged on this box, so `LinkedTree` has been
  silently using its `mklink /J` junction fallback all along.

  assertion that must go green to close this out, and it is the one I still cannot exercise locally."*
